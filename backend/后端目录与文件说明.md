# 后端目录与文件说明

本文档说明 `backend` 目录中每个文件夹和文件的作用，以及日常开发、配置和部署时应该注意的位置。

## 一、整体目录结构

```text
backend/
├─ app/                              FastAPI 网页接口与数据库业务
│  ├─ __init__.py                    Python 包标识
│  ├─ main.py                        后端入口与 API 路由
│  ├─ services.py                    诊断业务编排
│  ├─ database.py                    数据库连接和会话管理
│  ├─ models.py                      数据库表结构
│  └─ schemas.py                     API 请求与响应数据格式
├─ crop_disease/                     病害识别与建议生成核心代码
│  ├─ __init__.py                    Python 包标识和版本信息
│  ├─ diagnosis.py                   YOLO 模型加载与完整诊断流程
│  ├─ inference.py                   概率计算和作物类别约束
│  ├─ quality.py                     上传图片质量检查
│  ├─ rag.py                         本地知识库检索
│  ├─ advice.py                      AI 服务商调用与建议格式化
│  └─ credential_store.py            Windows 本机密钥读取与加密存储
├─ configs/
│  └─ inference.yaml                 模型、阈值、质量、RAG 和 AI 配置
├─ data/
│  └─ labels.json                    模型的 38 个类别及编号
├─ knowledge/
│  └─ disease_guidance.jsonl         病害防治知识库
├─ models/
│  └─ best.pt                        最终 YOLO 病害识别模型
├─ .env.example                      环境变量示例
├─ .gitignore                        不应提交的本机文件清单
├─ requirements.txt                  Python 依赖清单
├─ run.bat                           Windows 一键启动脚本
└─ README.md                         后端安装与启动说明
```

安装和运行后还可能自动出现 `.venv/`、`.local/` 和 `__pycache__/`。这些是运行环境、数据库或缓存，不属于手写源码。

## 二、`app` 网页后端目录

`app` 负责接收前端请求、调用识别服务、保存诊断记录并返回 JSON 数据。

### `app/main.py`

FastAPI 后端的主入口，创建 `app` 对象并定义网页使用的接口。目前主要包括：

- `GET /api/health`：检查后端和数据库状态；
- `GET /api/providers`：返回支持的 AI 服务商；
- `POST /api/providers/test`：测试 AI 接口配置；
- `GET /api/crops`：返回知识库已覆盖的作物和病害；
- `POST /api/diagnoses`：接收图片和现场信息并执行诊断；
- `GET /api/diagnoses`：查询当前浏览器用户的历史记录；
- `GET /api/diagnoses/{record_id}`：查看一条诊断记录详情。

这个文件还负责限制图片格式和大小、校验症状描述与用户编号、处理错误，以及配置前后端跨域访问。

新增或修改网页 API 时，通常从这里开始。

### `app/services.py`

连接网页接口和核心识别代码的业务层，负责：

1. 读取 `configs/inference.yaml`；
2. 加载模型类别和知识库；
3. 首次诊断时加载 YOLO 模型；
4. 根据用户选择的作物限制识别范围；
5. 检索对应的 RAG 知识；
6. 调用所选 AI 服务商生成中文建议；
7. 整理最终诊断结果和报告文本。

如果要改变“识别 → 知识检索 → AI 建议”的业务流程，主要修改这个文件。

### `app/database.py`

负责数据库连接、建表和会话管理。

- 没有设置 `DATABASE_URL` 时，默认使用 `.local/web.db` SQLite 数据库；
- 设置 `DATABASE_URL` 后可以连接 MySQL；
- 后端启动时会自动创建缺少的数据表；
- 每次 API 请求结束后会关闭数据库会话。

### `app/models.py`

使用 SQLAlchemy 描述数据库中的 `diagnosis_records` 表，包括：

- 诊断记录编号和浏览器用户编号；
- 作物、病害和置信度；
- 症状描述；
- 完整识别结果、AI 建议和报告；
- 创建时间。

修改表结构时要谨慎：已有数据库不会自动完成复杂字段迁移。

### `app/schemas.py`

使用 Pydantic 定义后端返回给前端的数据结构，例如作物选项、服务商信息、诊断记录和历史列表。

它可以保证接口输出格式稳定。新增返回字段时，通常需要同时修改 `schemas.py`、`main.py` 和前端接收代码。

### `app/__init__.py`

将 `app` 标记为可导入的 Python 包。一般不需要修改。

## 三、`crop_disease` 识别核心目录

这个目录是后端的算法核心，只保留线上运行真正需要的代码，没有训练、评估和数据集处理脚本。

### `crop_disease/diagnosis.py`

负责读取模型配置、加载 `best.pt`、运行 YOLO 分类，并把原始概率转换成诊断候选。它还会：

- 根据用户确认的作物过滤类别；
- 使用置信度阈值决定接受结果还是建议人工复核；
- 检查模型类别顺序是否与 `labels.json` 一致；
- 整合图片质量检查结果；
- 把英文类别转换成中文名称。

### `crop_disease/inference.py`

提供较小的概率处理函数，主要用于找出指定作物对应的类别，并对这些类别的概率重新归一化。

一般只有调整作物约束算法时才需要修改。

### `crop_disease/quality.py`

在模型识别前检查图片是否适合诊断，包括：

- 图片分辨率是否过低；
- 图片是否过暗或过曝；
- 图片是否过于模糊；
- 图片能否正常解码。

具体阈值不写死在这里，而是从 `configs/inference.yaml` 读取。

### `crop_disease/rag.py`

负责读取 `knowledge/disease_guidance.jsonl`，把知识内容切分，并使用 TF-IDF 检索与当前候选病害最相关的资料。

检索结果会作为证据交给 AI 服务商，减少建议偏离病害资料的风险。

### `crop_disease/advice.py`

负责 AI 建议功能，包括：

- DeepSeek、通义千问、智谱、Kimi、SiliconFlow 和自定义兼容接口配置；
- API 地址、模型名称与密钥格式校验；
- 防止访问不安全或本机私有地址；
- 构造带有诊断结果和 RAG 证据的提示内容；
- 调用 Chat Completions 兼容接口；
- 校验 AI 返回的 JSON；
- 生成前端显示的中文诊疗报告。

修改 AI 服务商、提示要求或报告格式时，主要查看这个文件。

### `crop_disease/credential_store.py`

用于在 Windows 中通过当前用户账户加密保存和读取后端兜底 API 密钥。当前网页也支持用户临时填写密钥，因此这个文件不一定会生成实际密钥文件。

不要复制或公开 `.local/deepseek_api_key.bin`；它既是敏感信息，也通常只能由原 Windows 用户解密。

### `crop_disease/__init__.py`

将目录标记为 Python 包，并记录核心包版本。一般不需要修改。

## 四、模型、标签、知识与配置

### `models/best.pt`

最终训练得到的 YOLO11n 分类模型，是图片病害识别的核心文件。删除后后端可以启动并查看作物列表，但真正提交图片诊断时会失败。

替换模型时必须确认新模型的类别数量和顺序与 `data/labels.json` 完全一致。

### `data/labels.json`

保存 38 个模型类别以及每个类别的编号。后端用它解释模型输出，并校验模型类别体系。

不要单独修改类别编号，也不要让它与 `best.pt` 来自不同训练版本。

### `knowledge/disease_guidance.jsonl`

本地病害知识库，每一行是一条 JSON 记录，包含作物、病害、症状、防治建议、来源机构和来源网址等信息。

网页只开放知识库已经覆盖的作物和病害。增加知识条目时应保持字段完整、病害标签与 `labels.json` 一致，并使用可靠来源。

### `configs/inference.yaml`

后端的主要运行配置，分为以下几类：

| 配置部分 | 作用 |
|---|---|
| `model`、`labels` | 模型和标签文件位置 |
| `image_size`、`top_k` | 模型输入尺寸和候选数量 |
| 拒识阈值 | 判断结果是否需要人工复核 |
| `quality` | 分辨率、亮度和清晰度检查阈值 |
| `deepseek` | 默认 AI 地址、模型、超时和输出参数 |
| `rag` | 知识库文件、分块长度和检索数量 |

拒识阈值来自模型验证结果，不建议凭感觉调整。替换模型后应该重新校准。

## 五、根目录文件

### `requirements.txt`

列出后端需要安装的 Python 第三方库：

- `fastapi`、`uvicorn`：网页 API 和服务器；
- `sqlalchemy`、`pymysql`：SQLite/MySQL 数据库；
- `ultralytics`：加载和运行 YOLO 模型；
- `numpy`、`Pillow`：图片读取和质量分析；
- `scikit-learn`：知识库 TF-IDF 检索；
- `PyYAML`：读取 YAML 配置；
- `python-multipart`：接收网页上传文件和表单；
- `pydantic`：接口数据校验。

执行 `pip install -r requirements.txt` 后，这些依赖会安装到 `.venv`。

### `.env.example`

环境变量示例文件。首次使用时可以复制成 `.env`，再填写实际配置：

- `DATABASE_URL`：数据库地址；留空使用 SQLite；
- `DEEPSEEK_API_KEY`：可选的后端兜底密钥；
- `WEB_ALLOWED_ORIGINS`：允许访问后端的前端地址；
- `INFERENCE_DEVICE`：使用自动、CPU 或 CUDA 推理；
- `MAX_UPLOAD_MB`：图片大小限制。

`.env.example` 可以保留和分享，但真正的 `.env` 可能包含密码或 API 密钥，不能公开。

### `run.bat`

Windows 一键启动文件。它会：

1. 检查 `.venv` 是否存在；
2. 读取 `.env` 中的环境变量；
3. 使用 Uvicorn 在 `127.0.0.1:8000` 启动 FastAPI。

### `.gitignore`

告诉 Git 忽略 `.venv`、`.local`、`.env`、Python 缓存和日志，避免提交体积较大的本机环境、历史数据库或敏感配置。

### `README.md`

记录后端虚拟环境创建、依赖安装、配置和启动方式。

## 六、运行后自动生成的目录

### `.venv/`

Python 虚拟环境，保存 Python 解释器和所有第三方依赖。它通常很大，不需要复制或提交；删除后可以根据 `requirements.txt` 重新创建。

### `.local/`

保存本机运行数据。默认情况下，SQLite 诊断数据库是 `.local/web.db`，还可能包含加密后的后端兜底密钥。

如果需要保留历史诊断记录，清理项目时不要误删 `.local/web.db`。

### `__pycache__/`

Python 自动生成的字节码缓存，用于加快模块加载。可以安全删除，重新运行后会自动生成。

## 七、一次诊断的完整流程

```text
前端上传图片和现场信息
          ↓
app/main.py 接收并校验请求
          ↓
app/services.py 编排诊断
          ↓
quality.py 检查图片质量
          ↓
diagnosis.py + best.pt 识别病害
          ↓
rag.py 从知识库检索对应资料
          ↓
advice.py 调用用户选择的 AI 服务商
          ↓
models.py / database.py 保存诊断记录
          ↓
schemas.py 约束结果格式并返回前端
```

## 八、常见修改位置

| 想要修改的内容 | 对应文件 |
|---|---|
| 新增或修改 API 接口 | `app/main.py` |
| 调整完整诊断业务流程 | `app/services.py` |
| 修改数据库连接 | `.env`、`app/database.py` |
| 修改诊断记录表结构 | `app/models.py` |
| 修改接口返回格式 | `app/schemas.py` |
| 调整模型判断与作物约束 | `crop_disease/diagnosis.py`、`inference.py` |
| 调整图片质量检查 | `configs/inference.yaml`、`quality.py` |
| 修改知识检索方法 | `crop_disease/rag.py` |
| 修改 AI 服务商、提示或报告 | `crop_disease/advice.py` |
| 增加病害知识 | `knowledge/disease_guidance.jsonl` |
| 替换识别模型 | `models/best.pt`，同时核对 `data/labels.json` |
| 修改端口 | `run.bat`，同时修改前端 `vite.config.js` |

## 九、启动与检查

1. 按 `README.md` 创建 `.venv` 并安装依赖；
2. 按需把 `.env.example` 复制为 `.env`；
3. 双击 `run.bat`；
4. 打开 `http://127.0.0.1:8000/api/health`，正常时应看到数据库状态为 `ok`；
5. 再启动相邻目录中的 `frontend/run.bat`。

后端窗口必须保持运行。首次提交诊断图片时才会真正加载模型，因此第一次诊断通常比之后稍慢。
